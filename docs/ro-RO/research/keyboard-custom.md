## Infundarea integrării

Majoritatea producătorilor oferă **software de configurare**, fără API de funcționare documentată public pentru programe terțe. Un macro/Remap configurat este tipic trimis ca o emisiune de tastatură HID; un buton sau un display nu se transformă într-o interfață de control standard Windows. Hardware-ul Hall/TMR recunoaște calea tastelor, dar aplicația primește valori analogice numai atunci când dispozitivul/modul specific le furnizează printr-o interfață adecvată. Wooting este cel mai clar în această selecție producător cu un adevărat public analog SDK; scopul SDK este integrarea nativă a intrărilor analogice în jocuri/aplicații. Acest lucru nu este un suport automat al oricărui model sau al oricărui producător.

**QMK vs. VIA: ** QMK este un firmware care este flăcat/construit; VIA este un configurator pentru dispozitive compatibile, respectiv flăcat. VIA poate configura straturi, straturi și în funcție de firmware macro / lumină, dar nici măcar nu este un API de timp de intrare generală. QMK / VIA compatibilitatea se aplică întotdeauna model / PCB / firmware-specific și niciodată pașal pentru întreaga marcă.

## Consecința unui controlor generic Windows

Pentru un sprijin puternic în primul rând **Calea normală a tastaturilor HID** utilizează (tasten, modificatori, cheltuieli macro). integrarea aplicațiilor / driverului este tratată ca un adaptor opțional, întreținut separat, fiecare după un protocol public dovedit / SDK. În modul analog nu se recunoaște doar „efectul de gătit”: se verifică în mod concret dacă modelul emite un HID de gamepad analog, un SDK specific producătorului sau doar evenimente digitale de tastatură. Wooting Analog SDK este cel mai bun punct de pornire pentru intrările continue reale; Keychron Q1 HE documentă funcțiile analog/gamepad, dar pagina de produs nu prezintă un SDK interproductiv.
