## USB VID/PID: límite de conocimiento

El descriptor de dispositivo USB contiene índices de descriptor de cadena de proveedor/producto, VID y PID, versión del dispositivo. El VID identifica al fabricante; El fabricante asigna el PID a un producto. Los campos estándar no contienen un “ANSI/ISO” estandarizado ni un campo de idioma/leyenda del teclado. El descriptor tiene un índice para una cadena de producto opcional; Este texto puede nombrar un modelo, pero no es un código de diseño estandarizado y no tiene por qué nombrar la variante específica. Un fabricante puede designar diferentes diseños con diferentes PID/SKU, pero la especificación USB no garantiza que les asignará diferentes ID. Por lo tanto, VID/PID solo identifica una variante de diseño específica si el fabricante publica la asignación exactamente para este modelo. Ni siquiera el nombre de un producto o el ID de hardware Windows reemplazan esta asignación.

Las tablas de uso de HID contienen controles opcionales para `Keyboard Physical Layout` (por ejemplo, 101/US, 102/German, 103/Korean, 104/ABNT Brasil, 106/Japanese) y `Keyboard IETF Language Tag`. Estos sólo se pueden utilizar si el dispositivo específico realmente los implementa en sus informes HID; no son subcampos VID/PID y no prometen los caracteres exactos impresos. Los usos de las teclas HID describen las entradas mientras el sistema operativo genera los caracteres utilizando el idioma activo/diseño de teclado. Además, ISO/ANSI Enter y una tecla ISO adicional pueden estar ubicadas de manera diferente, aunque muchas teclas reportan la misma función lógica.

Por lo tanto, para este catálogo de dispositivos: (1) Detecta la familia de productos mediante cadenas VID/PID/USB; (2) si se publica, asigne la variante mediante el SKU del fabricante/número de pieza o una revisión de hardware claramente conocida; (3) Guarde la geometría del diseño por separado como `ANSI`, `ISO`, `JIS`, `unknown`, solo con SKU o evidencia HID; (4) Mantenga el etiquetado/lenguaje separado, como `DE-QWERTZ`; (5) detecta unidades de control modulares por separado según el módulo existente y la posición izquierda/derecha/extraída; (6) le permite elegir un diseño si éste es desconocido o utilizar una representación honesta y neutral. Las teclas/marcadores de pantalla son controles específicos del fabricante y no pueden derivarse de la matriz de teclas de letras normal.

fuentes normales: [Microsoft USB_DEVICE_DESCRIPTOR](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbspec/ns-usbspec-_usb_device_descriptor) Describe `idVendor` como ID de vendedor concedido por el fabricante y `idProduct` como ID de producto específico de los fabricantes. [USB-IF Tables de uso](https://www.usb.org/sites/default/files/hut1_7.pdf) Documentar `Keyboard Physical Layout` y distinguir la orden física de las leyendas impresas; las tablas también definen el campo de lenguaje opcional.

## Notas sobre la precisión

- Una página de producto del fabricante con “diseño DE” confirma la versión del país/leyenda. No prueba necesariamente que una revisión específica vendida sea mecánicamente ISO. Cuando la fuente no lo menciona, la etiqueta de diseño sigue siendo provisional.
- Con GALLEON, el área de control 12er-LCD- debe visualizarse en su propia área; el número del botón UK/US/JP difiere según Corsair QSG. Las teclas de pantalla no son teclas HID alfanuméricas normales adicionales 12.
- En Dark Mount y Everest Max, el teclado numérico puede cambiar de lado. Una captura de pantalla o un esquema deben mostrar la página seleccionada y no deben suplantar la posición de la base de medios extraíbles/teclado numérico como una geometría estándar inmutable.
- Para K100, el banco de teclas G izquierdo y el grupo de control de medios superior se asignan como relacionados con el modelo; sólo la superficie del botón principal sigue la variante ANSI/ISO. Esto evita que un dibujo ISO genérico muestre accidentalmente el formulario Intro incorrecto o que falte una tecla adicional junto a Mayúsculas a la izquierda.
