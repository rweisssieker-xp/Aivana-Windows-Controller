# Special Features in Keyboards and Extra Keypads

[English (US)](../../en-US/research/keyboard-productivity.md) · [Deutsch](../../de-DE/research/keyboard-productivity.md) · [Français](../../fr-FR/research/keyboard-productivity.md) · [Italiano](../../it-IT/research/keyboard-productivity.md)

Research from official manufacturer pages, product sheets, and manuals (as of October 8, 2026). This is a feature and integration overview, not a guarantee of availability: older products may still have software downloads even after the device is discontinued or available only secondhand.

**For Windows controller integration, the key distinction is:** standard keyboard, consumer-control, mouse, or gamepad HID events can be used as input. Manufacturer software may also run background actions or control a device through a manufacturer-specific channel. An RGB/lighting API is not an API for keyboard events. “Not documented” means only that the manufacturer materials reviewed do not describe a suitable public input/device API.

## Practical interpretation

The broadest brand-independent support comes from programmed keys that emit standard HID keyboard or multimedia shortcuts. An app can process those shortcut keys just like ordinary combinations. In this brand sample, X-keys (Windows SDK/HID), Tipro MIDAPI, and PrehKeyTec MWXUSB/OPOS are also credible paths for direct device integration; they are specialty devices and do not represent consumer keyboards. Das Keyboard's Q REST API, by contrast, is specifically documented for key-light signals and event indicators. For the other gaming and ergonomic products listed, manufacturer pages mainly document configuration in the manufacturer's app, onboard storage, and keyboard shortcut output; a public runtime API for third-party software is not documented here.
