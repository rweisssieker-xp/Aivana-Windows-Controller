# Special functions of keyboards and additional keypads

[English (US)](keyboard-productivity.md) | [Deutsch](keyboard-productivity.md) | [Français](keyboard-productivity.md) | [Italiano](keyboard-productivity.md)

Research from official manufacturer websites, product data sheets and manuals (as of October 8 2026). This is a function and integration overview, not an availability guarantee: For older products, software can still be offered as a download even though the device itself is discontinued or is only available used.

**For the Windows controller integration, the distinction counts:** Normal keyboard, consumer control, mouse or gamepad HID events can be used as inputs. Manufacturer software can also perform actions in the background or control a device via a manufacturer channel. An RGB/light API is not an API for button events. “Not proven” here only means that the evaluated manufacturer documents do not document a suitable public input/device API.

## Practical classification

The broadest support without vendor lock-in is provided by programmed keys that emit standard HID keyboard or multimedia shortcuts. An application can process such shortcut keys in the same way as normal combinations. Also reliable for direct device integration in this brand sample are X-keys (Windows-SDK/HID), Tipro MIDAPI and PrehKeyTec MWXUSB/OPOS; they are specialized devices, not representative of consumer keyboards. The Das-Keyboard Q-REST API, on the other hand, is explicitly documented for key lights and event indicators. For the other gaming and ergo products mentioned, the manufacturer's websites primarily cover configuration via the respective manufacturer's app, onboard storage and output of keyboard shortcuts; A public runtime API for third-party software is not documented here.
