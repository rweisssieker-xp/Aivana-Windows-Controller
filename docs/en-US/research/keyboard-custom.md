## Integration findings

Most manufacturers provide ** configuration software**, no publicly documented runtime API for third-party programs. A configured macro/remap is typically sent as normal HID keyboard output; This does not make a knob or display a standardized Windows controller interface. Hall/TMR hardware recognizes key travel, but the application only gets analog values ​​if the specific device/mode provides them via a suitable interface. Wooting is the most clearly documented manufacturer in this selection with a real public analog SDK; the SDK purpose is native integration of analog input into games/apps. This is not automatic support for every model or every manufacturer.

**QMK vs. VIA:** QMK is firmware that is flashed/built; VIA is a configurator for compatible, appropriately flashed devices. VIA can configure assignments, layers and, depending on the firmware, macros/light, but is not itself a general input runtime API. QMK-/VIA compatibility is always model/PCB/firmware specific and never across the board for an entire brand.

## Consequence for a generic Windows controller

For robust support, first use the **normal HID keyboard path** (keys, modifiers, macro outputs). Treat app/driver integration as optional, separately maintained adapters, each only according to verifiable public protocol/SDK. Don't just recognize the “Hall Effect” in analog mode: specifically check whether the model outputs analog gamepad HID, a manufacturer-specific SDK or just digital keyboard events. Of the vendor sources documented here, Wooting Analog SDK is the best starting point for true continuous input; Keychron Q1 HE documents analog/gamepad functions, but the product page does not document a cross-vendor SDK.
