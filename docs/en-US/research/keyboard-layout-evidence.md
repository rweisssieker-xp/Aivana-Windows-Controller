## USB VID/PID: knowledge limit

The USB device descriptor contains VID and PID, device version, and vendor/product string descriptor indexes. The VID identifies the manufacturer; The manufacturer assigns the PID to a product. The standard fields do not contain a standardized “ANSI/ISO” or keyboard legend/language field. The descriptor does have an index for an optional product string; This text can name a model, but is not a standardized layout code and does not have to name the specific variant. A manufacturer can designate different layouts with different PIDs/SKUs, but the USB specification does not guarantee that they will assign different IDs for them. VID/PID therefore only identify a specific layout variant if the manufacturer publishes the assignment for exactly this model. Even a product name or Windows hardware ID does not replace this assignment.

HID Usage Tables contain optional controls for `Keyboard Physical Layout` (e.g. 101/US, 102/German, 103/Korean, 104/ABNT Brazil, 106/Japanese) and `Keyboard IETF Language Tag`. These can only be used if the specific device actually implements them in its HID reports; they are not VID/PID subfields and do not promise the exact characters printed. The HID key usages describe inputs while the operating system generates the characters using the active language/keyboard layout. In addition, ISO/ANSI Enter and an additional ISO key may be located differently, although many keys report the same logical function.

For this device catalog therefore: (1) Detect product family via VID/PID/USB strings; (2) if published, assign variant via manufacturer SKU/part number or clearly known hardware revision; (3) Save layout geometry separately as `ANSI`, `ISO`, `JIS`, `unknown`, with SKU or HID evidence only; (4) Keep labeling/language separate, like `DE-QWERTZ`; (5) detect modular control units separately according to existing module and position left/right/removed; (6) let you choose a layout if the layout is unknown or use an honest, neutral representation. Display keys/dials are manufacturer-specific controls and cannot be derived from the normal letter-key matrix.

The normal sources: [Microsoft USB_DEVICE_DESCRIPTOR](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbspec/ns-usbspec-_usb_device_descriptor) describes `idVendor` as the vendor ID provided by the manufacturer and `idProduct` as the product ID provided by it. [USB-IF HID Usage Tables](https://www.usb.org/sites/default/files/hut1_7.pdf) documenting `Keyboard Physical Layout` and clearly distinguishing the physical order from the printed legends; the tables also define the optional language-day field.

## Notes on accuracy

- A manufacturer product page with “DE layout” confirms the country/legend version. It does not necessarily prove that a specific revision sold is mechanically ISO. Where the source does not mention either, the layout label remains provisional.
- With GALLEON, the 12er-LCD- control area must be displayed in its own area; the UK/US/JP button number differs according to Corsair QSG. Screen keys are not 12 additional normal alphanumeric HID keys.
- On Dark Mount and Everest Max, the Numpad can change sides. A screenshot or schematic must show the selected page and must not impersonate the removable media dock/numpad position as an immutable standard geometry.
- For K100, the left G-key bank and upper media control cluster is assigned as model related; only the main button surface follows the ANSI/ISO variant. This prevents a generic ISO drawing from accidentally showing the wrong Enter form or a missing additional key next to Left Shift.
