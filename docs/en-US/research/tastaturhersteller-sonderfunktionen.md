As of October 8, 2026. This broad, source-linked inventory contains 74 manufacturer/brand entries from three research groups and 14 additional brands. It is **not a complete worldwide list** or a guarantee of availability; products, revisions, drivers, and firmware may vary. ASRock Phantom Gaming was reviewed but was not confirmed as a standalone keyboard brand in the official sources examined, so it is not counted as a manufacturer entry. Corsair/Elgato remains included as a keyboard/accessory brand; Stream Deck hardware and its SDK are considered separately.

## What can actually be integrated

A standard HID keycode, consumer-control media key, mouse event, or gamepad report can be used as ordinary Windows input. Manufacturer macros and onboard layers usually emit these same key sequences. A proprietary configuration program lets users set assignments, but it is not automatically a runtime API for third-party software. Public SDKs should be separated by purpose: **input/device APIs** (for example, Wooting Analog SDK, X-keys Windows SDK, Tipro MIDAPI, and PrehKeyTec MWXUSB); **game-event/display or macro-key integration** (model/software-specific, such as Logitech G-keys); and **RGB/lighting APIs** (such as ASUS Aura, Razer Chroma, MSI Mystic Light, Corsair iCUE, and Das Keyboard Q API). A lighting API does not automatically read or remap keystrokes. “Not documented” means only that the linked official materials do not describe a suitable public input interface.

USB vendor identification (VID/PID) should not be treated as a complete determination of physical geometry or layout: the same product name can have multiple SKUs/PCBs, ANSI/ISO editions, language layouts, and revisions; modular numpads/docks can be placed on the left, right, or separately. For reliable profiles, record **model + SKU + ANSI/ISO + language + revision + modular placement** explicitly. For analog/Hall-effect/optical devices, also check whether the current mode actually reports analog gamepad HID values or only digital keyboard events.

## Implications for product planning

The broadest cross-brand baseline is processing ordinary Windows input; programmed macros and layers should be expected to emit standard keycodes. Direct integration with special devices should be optional and implemented as an adapter tested against the exact device. Publicly documented specialist paths in this sample include Wooting analog data, X-keys device access, Tipro MIDAPI, and PrehKeyTec MWXUSB/OPOS. Logitech G-keys and similar extra buttons depend on specific model/software combinations. RGB SDKs are useful for feedback, not for reading user input. Display, encoder, touch, or analog features always require the exact device variant.
