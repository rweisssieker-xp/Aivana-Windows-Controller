Η εφαρμογή κατασκευάστηκε κάτω από Windows x64 με το σταθερό .NET SDK 10.0.202 και δημοσιεύθηκε ως ανεξάρτητο Windows-x64-Ausgabe.

## Αυτόματη Ελέγχου

- Συνολική κατασκευή: χωρίς προειδοποιήσεις και χωρίς σφάλματα.
- 19 Κορυφαία δοκιμές συμπεριφοράς: τυποποιημένη διαμόρφωση, επικύρωση, μηδενική / διπλή δεδομένα, προτεραιότητα προφίλ, εισαγωγή / εξαγωγή και αποκατάσταση ασφαλείας, σειρά μακρογραφίας και επαναλήψεων, αποσύνθεση, διπλή εκκίνηση, σειρά, αμετάβλητη εκτέλεση και σφάλματα βήματος.
- Windows εξέταση: ομαλοποίηση κλειδιών και ονομασίες αλυσίδας, οικιακές διαστάσεις δομής, πραγματική λίστα πλήκτρων συσκευών, ασφαλή εγγραφή και επαναφορά, συνθετική WM_HOTKEY για κλειδιά και αποσύνθεση, απενεργοποιημένη εγγραφή κλειδιού κατά τη διάρκεια της προσομοίωσης εισόδου.
- Η ανεξάρτητη EXE ξεκίνησε με `--smoke-test`: αποσπά όλες τις πέντε προβολές WPF, μπορούν να εγκατασταθούν / να αντιγραφούν / να διαγραφούν, τα σχέδια παραμένουν αποθηκευμένα κατά την αναζωογόνηση, η διαμόρφωση αποθηκεύεται και επαναφορτώνεται. Αυτή η δοκιμή χρησιμοποιεί ένα απομονωμένο προσωρινό κατάλογο διαμόρφωσης και δεν εκτελεί πράξεις κειμένου ή μέσων ενημέρωσης.
- Το δίσκο, ο επεξεργαστής και η συμπαγή απεικόνιση (900 × 720) ελέγχθηκαν οπτικά ως πραγματικές WPF τάσεις. Σχεδιασμός αποθήκευσης, απόρριψη, κασέτα / μακρο-συστήματα, γερμανική συμμαχία hotkey, μεμονωμένες μακρο-αποκρίσεις και βήμα-βήμα εξετάζονται.

## Τα όρια εξαρτησίας

Η τελευταία τοπική διέλευση αναγνώρισε τέσσερις Windows συνδέσεις πληκτρολογίου. Ο αριθμός αυτός περιγράφει τις διεπαφές HID/Windows, όχι απαραίτητα τέσσερις φυσικές πληκτρολογίες.

Το επίσημο iCUE SDK είναι εγκατεστημένο και βρίσκεται δίπλα στο EXE. Η ζωντανή δοκιμή συνδέεται με το iCUE και αναγνωρίζει ένα πληκτρολόγιο Corsair με πληροφορίες μοντέλου και LED. Οι αλλαγές φωτισμού δεν έγιναν αυτόματα, οι πινακίδες εξάρτησης μοντέλου και άλλοι κατασκευαστές δεν δοκιμάστηκαν με υλικό. Τα γενικά hotkeys ισχύουν διασταυρωτικά.

Οι εισαγωγές κειμένου/μέσων δεν έχουν ενσωματωθεί σε άλλα ανοιχτά προγράμματα χρήσης. Οι εγχώριες δομές δεδομένων και η λογική σφάλματος/ελευθέρωσης έχουν εξεταστεί· η συμπεριφορά σε ένα συγκεκριμένο πρόγραμμα-στόχο εξαρτάται, μεταξύ άλλων, από το επίπεδο επιλεξιμότητάς του.

## Επαναλάβετε

```powershell
dotnet build Aivana.slnx -c Release
dotnet run --project tests/Aivana.Tests -c Release
dotnet run --project tests/Aivana.Windows.Tests -c Release
dotnet publish src/Aivana.Desktop -c Release -r win-x64 --self-contained true -o artifacts/win-x64
& ./artifacts/win-x64/MAKRIVO.exe --smoke-test
```

Η δοκιμή GUI γράφει το αποτέλεσμα και τη λήψη οθόνης μετά από `smoke` δίπλα στο ελέγχον EXE. Σκεφτείται ως διάγνωση και μετά την ολοκλήρωση δεν ξεκινάει μόνιμη παρακολούθηση.


## Διευρυμένο έλεγχο

Επιπλέον, ελέγχονται: συνθήκες προφίλ με τη διαδικασία και τους τίτλους των παραθύρων, μεταβλητές χωρίς αναδρομική επέκταση, μακροπροσκόπηση χωρίς εκτέλεση, νέα επικύρωση δράσης και ανοδική συμβατότητα παλιών αρχείων JSON. Οι εγχώριες δοκιμές καλύπτουν το πακέτο εντολών με την εγγραφή, τις συγκρούσεις, τη διάθεση και την απελευθέρωση του WM_HOTKEY, καθώς και την καθαρή κατανομή παρακολούθησης και την πρόσβαση σε κλιπμπούρ που βασίζεται στις ανάγκες. Η δοκιμή WPF ανοίγει και εκτελεί την πραγματική παλέτα, εξετάζει τα πίσω / επαναλαμβανόμενα και τα αγαπημένα, εξετάζουν τα καθαρά σχέδια μετά την εκτελέση και ολοκληρώνουν με επιτυχία τη διαδικασία.

Το Windows μπλοκάρισμα, οι αλλαγές διασταύρωσης και οι κινήσεις των παραθύρων δεν εφαρμόστηκαν στα προγράμματα χρήσης κατά τη διάρκεια των δοκιμών. Οι δράσεις παράθυρα δημοσιεύουν αιτήματα Windows ασύγχρονες· το συγκεκριμένο πρόγραμμα-στόχο μπορεί να έχει τα δικά του ελάχιστα μεγέθη ή όρια επιλεξιμότητας. Το κλείσιμο προφίλ και οι στατιστικές εκτέλεσης ισχύουν για τη συνεδρίαση.
