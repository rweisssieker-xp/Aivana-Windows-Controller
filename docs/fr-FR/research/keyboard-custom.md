# Marques de claviers et fonctions spéciales — recherche pour le contrôleur Windows

[English (en-US)](../../en-US/research/keyboard-custom.md) | [Deutsch (de-DE)](../../de-DE/research/keyboard-custom.md) | [Français (fr-FR)](keyboard-custom.md) | [Italiano (it-IT)](../../it-IT/research/keyboard-custom.md)

État au 8 octobre 2026. Échantillon de 24 marques demandées, sans prétention à constituer un répertoire mondial exhaustif. Ici, « fonction spéciale » désigne la détection analogique matérielle ou micrologicielle (Hall/TMR), Rapid Trigger, fonctions de touche dynamiques, macros, couches, boutons, écrans ou configuration comparable. Les liens renvoient principalement aux pages produits, d’assistance ou de téléchargement des fabricants.

## Résultats concernant l’intégration

La plupart des fabricants proposent un **logiciel de configuration**, et non une API d’exécution documentée publiquement pour les programmes tiers. Une macro ou une affectation configurée est généralement envoyée comme une sortie clavier HID ordinaire ; un bouton rotatif ou un écran ne devient pas pour autant une interface standard de contrôleur Windows. Le matériel Hall/TMR détecte la course des touches, mais l’application ne reçoit des valeurs analogiques que si le périphérique et le mode concernés les fournissent via une interface adaptée. Dans cet échantillon, Wooting est le fabricant dont le SDK analogique public est le mieux documenté ; il sert à intégrer nativement des entrées analogiques aux jeux et applications. Cela ne garantit pas la prise en charge automatique de tous ses modèles ni de toutes les marques.

**QMK et VIA :** QMK est un micrologiciel à compiler ou à flasher ; VIA est un configurateur pour les périphériques compatibles dotés du micrologiciel approprié. VIA peut configurer les affectations, couches et, selon le micrologiciel, macros et éclairages ; ce n’est pas une API générale d’entrée à l’exécution. La compatibilité QMK/VIA dépend toujours du modèle, du PCB et du micrologiciel, jamais de la marque entière.

## Conséquence pour un contrôleur Windows générique

Pour une prise en charge robuste, commencer par le **chemin clavier HID ordinaire** (touches, modificateurs, sorties de macros). Traiter l’intégration aux applications/pilotes comme des adaptateurs facultatifs maintenus séparément, chacun fondé sur un protocole ou SDK public attesté. Pour le mode analogique, ne pas se contenter de reconnaître « Hall Effect » : vérifier si le modèle fournit un HID de manette analogique, un SDK propriétaire ou uniquement des événements clavier numériques. Parmi les sources fabricant présentées ici, le SDK analogique Wooting est le meilleur point de départ pour des entrées continues réelles ; le Q1 HE de Keychron documente des fonctions analogiques/de manette, mais sa page produit n’atteste pas de SDK interopérable.
