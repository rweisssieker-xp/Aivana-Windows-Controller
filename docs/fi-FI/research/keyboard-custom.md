## Integraatiopiste

Useimmat valmistajat tarjoavat **konfiguratiivisen ohjelmiston**, ei julkisesti dokumentoitu käyttöiän API kolmannen osapuolen ohjelmiin. Konfiguroitu makro/remap lähetetään tyypillisesti normaalin HID-näppäimistöön, jolloin painiketta tai näytettä ei muuteta standardoituneeksi Windows -ohjainliittymäksi. Hall-/TMR-laitteisto tunnistaa painikkeita, mutta sovellus saa analogisia arvoja vain, jos konkreettinen laite/tila tarjoaa sen sopivalla käyttöliittymällä. Wooting tässä valinnassa on selkein valmistaja, jolla on todellinen julkinen analoginen SDK; SDK-tavoite on kotimainen integrointi analogisia sisäänkäyntejä peleihin/sovelluksiin. Tämä ei ole automaattinen tuki jokaiselle mallille tai valmistajalle.

**QMK vs. VIA:** QMK Firmware, joka on rakennettu; VIA on yhteensopiva, mukaisesti flakattu laite. VIA pystyy määrittämään laitteet, laitteet ja firmware makroja / valoa, mutta ei edes yleinen sisäänkäynti-Runtime API. QMK-/VIA-Yhteensopivuus on aina malli-/PCB/yritysohjelmisto ja ei koskaan kiinteä koko brändi.

## Yleinen Windows -ohjain

Vahvan tuen saamiseksi käytä ensin **normaalia HID-näppäimistöä** (näppäimet, muuttujat, makrokulut). Sovellusten/ohjainten integrointi käsitellään valinnaisina ja erikseen ylläpidettavina sovelluksina vain todennettavan julkisen pöytäkirjan/SDK:n mukaisesti. Analogi-tilassa ei tunneta pelkästään ”Hall Effect”: tarkistaa konkreettisesti, että malli antaa analogisen Gamepadin HID: n, valmistajan erityisen SDK: n tai vain digitaalisen painikkeiden tapahtumien. Tuotantolähteistä Wooting Analog SDK on paras lähtökohta todellisille jatkuville sisäänkäynneille; Keychron Q1 HE dokumentoi analogiset/gamepad-toimintoja, mutta tuote-sivulla ei ole valmistajan välistä SDK:tä.
