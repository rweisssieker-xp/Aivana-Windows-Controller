## Descobertas de integração

A maioria dos fabricantes fornece software de configuração ****, nenhuma API de tempo de execução documentada publicamente para programas de terceiros. Uma macro/remapeamento configurado normalmente é enviado como saída normal de teclado HID; Isso não cria um botão nem exibe uma interface de controlador Windows padronizada. O hardware Hall/TMR reconhece o deslocamento das teclas, mas o aplicativo só obtém valores analógicos se o dispositivo/modo específico os fornecer por meio de uma interface adequada. Wooting é o fabricante mais claramente documentado nesta seleção com um SDK analógico público real; o objetivo do SDK é a integração nativa de entrada analógica em jogos/aplicativos. Este não é um suporte automático para todos os modelos ou fabricantes.

**QMK vs. VIA:** QMK é um firmware atualizado/construído; VIA é um configurador para dispositivos compatíveis e com flash adequado. VIA pode configurar atribuições, camadas e, dependendo do firmware, macros/light, mas não é em si uma API de tempo de execução de entrada geral. A compatibilidade QMK-/VIA é sempre específica do modelo/PCB/firmware e nunca generalizada para uma marca inteira.

## Consequência para um controlador Windows genérico

Para suporte robusto, primeiro use o caminho de teclado HID normal **** (teclas, modificadores, saídas de macro). Trate a integração de aplicativo/driver como adaptadores opcionais mantidos separadamente, cada um apenas de acordo com o protocolo/SDK público verificável. Não reconheça apenas o “Efeito Hall” no modo analógico: verifique especificamente se o modelo gera HID de gamepad analógico, um SDK específico do fabricante ou apenas eventos de teclado digital. Das fontes de fornecedores documentadas aqui, Wooting Analog SDK é o melhor ponto de partida para uma entrada verdadeiramente contínua; Keychron Q1 HE documenta funções analógicas/gamepad, mas a página do produto não documenta um SDK de vários fornecedores.
