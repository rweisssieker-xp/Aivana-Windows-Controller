# Перевірка – 8. Жовтень 2026

Пристрій був побудований під Windows x64 з стабільним .NET SDK 10.0.202 і опублікований як самостійний Windows-x64-Ausgabe.

## Автоматично перевірено

- Загальна конструкція: немає попереджень і помилок.
- 19 Тести поведінки ядра: стандартна конфігурація, аутентифікація, нуль/двоповерхові дані, пріоритет профілю, імпорт/експорт і відновлення резерву, макрорегіон і повторення, розрив, подвійне розширення, серіалізація, незмінний відбиток виконання і помилки.
- Windows тестування: нормалізація і ім'я аліасів, внутрішні розміри структури, реальний список клавіатури, безпечна реєстрація і відтворення, синтетичний WM_HOTKEY для кашель і розриву, деактивована реєстрація кашель під час введення симуляції.
- Незалежний EXE був запущений з `--smoke-test`: всі п'ять WPF поглядів можна завантажити/копіювати/розчиняти, дизайн зберігається під час відновлення, конфігурація зберігається і перезавантажується. Цей тест використовує ізольований тимчасовий каталог конфігурації і не виконує текстові або медіа-акції.
- Дашборд, редактор і компактна презентація (900 × 720) були візуально перевірені як реальні WPF рендери. Розробка, відхилення, кашель/макро-порядження, німецька гаткі альянс, індивідуальні макро-розриви і кроковий прогрес перевіряються.

## Границі харчування

Останній місцевий прохід розпізнав чотири Windows клавіатурні інтерфейси. Ця цифра описує HID/Windows інтерфейси, не обов'язково чотири фізичні клавіші.

Офіційний SDK iCUE встановлений і розташований поруч з EXE. Живий тест з'єднується з iCUE і розпізнає клавіатуру Corsair з інформацією про модель і світлодіод. Зміни в освітленні не відбулися автоматично; залежно від моделі клавіші і інші виробники не перевіряються. Геніальні клавіатури застосовуються між клавіатурами.

Введення тексту/медіа не вводилося в інші відкриті програми користувачів. Внутрішні структури даних та логіка помилок / випуску були перевірені; поведінка в конкретній цільовій програмі залежить, серед іншого, від її рівня допустимості.

## Повторювати

```powershell
dotnet build Aivana.slnx -c Release
dotnet run --project tests/Aivana.Tests -c Release
dotnet run --project tests/Aivana.Windows.Tests -c Release
dotnet publish src/Aivana.Desktop -c Release -r win-x64 --self-contained true -o artifacts/win-x64
& ./artifacts/win-x64/MAKRIVO.exe --smoke-test
```

В результаті тестування GUI записується результат і знімки екрану за `smoke` поряд з перевіреним EXE. Він розглядається як діагностичний режим і після закінчення не починається постійний фон.
