# MAKRIVO purchase terms snapshot — review only

This change prepares **test-mode evidence**, not a completed contract-confirmation delivery. Live checkout is hard-blocked in `ready()` until durable delivery, separate declarations, timing, failure handling and legal sign-off are implemented and verified. Existing payment webhooks, paid-order access and activation remain independently available: this is a new-sales gate, not retroactive revocation.

Before a test checkout, create and check a backup of the chosen isolated database, apply `migrations/0004_contract_acceptances.sql` exactly once, and insert separately reviewed, versioned DE/EN plain-text purchase terms in `contract_documents`; use LF line endings (CR/CRLF and control characters are rejected). Set `CONTRACT_VERSION_DE` and `CONTRACT_VERSION_EN` to the exact version identifiers; use ASCII letters, numbers, dots, hyphens or underscores (1–64 characters). No production or customer-facing wording is supplied here. New checkouts stay disabled if either version, text, D1 table or any other readiness condition is missing. D1 stores full documents rather than Worker environment variables, which are limited to [5 KB each](https://developers.cloudflare.com/workers/platform/limits/).

The German and English page displays the selected exact text as escaped plain text. The browser sends the digest of language, version and text with its checkbox. At preparation, the Worker compares it with the current server document, then stores the document copy, version, language, digest and the server time of the checkbox assertion in the same atomic D1 batch as the order and checkout attempt. This is evidence of what the server rendered and a submitted checkbox assertion, not proof the customer read, understood or personally made a legally sufficient declaration. Insert/replace, update and delete triggers reject routine changes to a stored document version or stored acceptance. This intentionally blocks ordinary deletion of acceptance data; a separate controlled retention/deletion procedure still needs to be designed and approved. Database administrators can override triggers, so access controls, backup and audit remain required. To change terms, insert a new version and switch the relevant configured version; old acceptances retain their original text. Existing in-flight Workers may still use their own deployment configuration.

A paid, authenticated buyer can download the saved terms text through `POST /api/order/terms` with the exact configured Origin; a refund does not remove access to the copy. The purchase page initiates this request on a button click, using the existing HttpOnly cookie without exposing it to JavaScript. Top-level GET and foreign-origin POST do not download the document. Legacy orders without recorded terms receive no invented document. The returned file is only the saved terms copy, not a full contract confirmation or proof of delivery. No separate early-performance consent or acknowledgement of withdrawal consequences is recorded. The Stripe-hosted terms URL is configured separately and must be reviewed for consistency with the displayed version. No email service, delivery receipts, retry queue, provider contracts, actual legal content or deletion schedule has been configured.

Before any live acceptance: complete and approve the full legal documents and regional scope; separately design and test required declarations and durable confirmation delivery before entitlement release; establish real recipient, provider, bounce/retry, privacy, retention and support processes; run a real Stripe/Cloudflare isolated end-to-end test, including race, retry, refund and failure cases; verify the precise deployed app/package. Restrict operator write access to version configuration and D1. The `adaptive_pricing[enabled]=false` request prevents automatic localized-price display; verify the configured Stripe API version supports it, alongside the still-open tax configuration. See [Stripe Checkout Session creation](https://docs.stripe.com/api/checkout/sessions/create#create_checkout_session-adaptive_pricing-enabled).
